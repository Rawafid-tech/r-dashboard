# Part 1 — Mylerz

> Builds on `2026-10-24-wavex.md` Part 1 (a pickup-address picker filled by Test Connection) and on
> `2026-10-30-jt-express.md` Part 1 (an admin-added own-API carrier whose row holds a `returns`
> switch).

**Status: deployed to staging (PR #77, 2026-11-06), row `mylerz` added DISABLED.** All 134 zones
synced and placed. It was checked against a local stand-in only: the Mylerz logins we tried were
refused, so nothing has been confirmed against the live Mylerz API. The row is enabled once a real
login has been checked; until then merchants do not see Mylerz.

Mylerz runs its own API (platform `MYLERZ`). There is **no new API shape**: `fields` and
`capabilities` drive every screen, as for every other carrier.

What is different, and what the screens must handle:

- **Admin-added, like J&T.** `GET /api/admin/carrier-platforms` lists `MYLERZ` with one carrier field,
  `returns` (BOOLEAN, default `false`). The row holds no sync account: Mylerz's zone list ships with
  the backend.
- **Connect with a login, then pick a warehouse.**
  - `username` and `password` are both `SECRET`: the merchant's Mylerz integration login.
  - `warehouse` is a `PICKUP_LOCATION`. Test Connection fills `pickupLocations` from the warehouses on
    the account, the same way it fills Wavex's addresses. Each one's `id` and `name` are both the
    warehouse name, and `isDefault` is the default Mylerz marks, if it marks one.
  - If the merchant picks no warehouse, the account's default is used, or its only warehouse. An
    account with several warehouses and no default can't book until one is picked: the booking
    answers the usual `carrier.booking.pickupLocation`.
  - `merchantId` (TEXT, optional) is the merchant id Mylerz issues. It is only sent with cancels;
    anything other than digits answers the usual `400 carrier.invalidField`.
  - `allowOpen` (BOOLEAN, default `false`) lets the customer open the parcel.
- **Capabilities.** `labels: true`, `cancel: true`, `tracking: true`, `exchanges: false`,
  `refunds: false`, `pushUrl: false`. `returns` follows the admin switch (`false` until it is turned
  on).
- **Labels.** Mylerz prints one label per call, so the backend fetches each label and merges them.
  `POST /api/shipments/labels` still returns one PDF, a page per shipment, and the 50-shipment limit
  is unchanged. A print of many shipments takes longer than Bosta's.
- **Returns, when switched on,** are collected from the customer and prepaid: no amount is collected
  and no refund is handed out (`refunds: false`). The customer may not open a return.
- **Cancel** is by waybill, before pickup. After pickup it answers the usual
  `409 carrier.booking.notAllowed`.
- **Tracking is polled.** Mylerz can push to a webhook, but only one registered under the
  merchant id, so pushes are not wired up yet.
- **Areas.** The backend ships Mylerz's city and zone codes. There are 134 zones in 30 cities: 51 in
  Cairo and 36 in Giza, and most other governorates are a single zone. Mylerz files Shubra El Kheima,
  El Obour, 10th of Ramadan and El Saf under Cairo; the backend places each of these in its own
  governorate. North Coast and International are left out. Nothing changes on screen:
  `address.method` and `district.method` work as before.

## 1. Merchant screens

**Connect form.** `GET /api/carriers` lists the Mylerz row with five `fields`:

```json
{ "code": "mylerz", "fields": [
    { "key": "username",   "kind": "SECRET",          "required": true,
      "label": "Username (your Mylerz integration login)" },
    { "key": "password",   "kind": "SECRET",          "required": true,  "label": "Password" },
    { "key": "warehouse",  "kind": "PICKUP_LOCATION", "required": false, "label": "Pickup warehouse" },
    { "key": "merchantId", "kind": "TEXT",            "required": false,
      "label": "Merchant ID (from Mylerz; optional, used to cancel shipments)" },
    { "key": "allowOpen",  "kind": "BOOLEAN",         "required": false, "defaultValue": false,
      "label": "Allow the customer to open the parcel" } ],
  "capabilities": { "labels": true, "cancel": true, "tracking": true, "returns": false,
                    "exchanges": false, "refunds": false, "pushUrl": false } }
```

The two secrets travel in `credentials`. `warehouse`, `merchantId` and `allowOpen` travel in
`options`. The Arabic labels come back under `Accept-Language: ar` as usual.

**Test Connection** (`POST /api/carriers/{code}/test`, with `credentials` only) logs in and lists the
warehouses:

```json
{ "pickupLocations": [
    { "id": "Main Warehouse", "name": "Main Warehouse", "address": "12 Street 9, Maadi",
      "isDefault": true },
    { "id": "Giza Store", "name": "Giza Store", "address": null, "isDefault": false } ],
  "warnings": [] }
```

A wrong login answers the usual `422`. A `warehouse` on create or update that isn't one of these
answers the usual `422 carrier.pickupLocationNotOnAccount`. Per-sender-location warehouse mappings
work as they do for Bosta and Wavex.

## 2. Admin screens

Add the carrier from the platform form (`platform: "MYLERZ"`, `settings: {}`). Turn on
`settings.returns` (`"true"`) to offer returns. Sync its areas with the usual
`POST /api/admin/carriers/{code}/regions/sync`, which needs no account. The logo, enable switch and
list work as for any other row.

## 3. What did not change

There is no new endpoint, error code or field kind. Booking, preview, bulk booking, the timeline,
notifications and labels all behave as they do for the other carriers.
