# Part 1 — Wavex

> Builds on `2026-10-23-wingezz.md` Part 1 (an own-API carrier added from the admin form, a sealed
> sync secret on its row) and `2026-10-09-pickup-locations-notifications.md` Part 1 (pickup
> locations per sender location).

**Status: deployed to staging (PR #63, 2026-10-24).** On staging Wavex (`wavex`) is added and
enabled with its sync token (507 cities, every governorate placed). One test parcel was booked
through staging (airway bill `C0BMSF9UVMXF`), then cancelled through staging and confirmed cancelled
on Wavex. ~~It has no logo yet (`logoUrl: null`).~~ Its logo was uploaded on 2026-10-24.

Wavex has its own API (platform `WAVEX`). An admin adds it from the admin form, and merchants
connect, book, track and cancel. **No FE change specific to Wavex**: every screen is driven by
`fields`, `carrierFields` and `capabilities`, and its pickup picker is the one Bosta already uses.

What is different, and what the screens must handle:

- **Cancel works and print doesn't.** `capabilities` is `cancel: true`, `labels: false`,
  `tracking: true`, `exchanges: false` and `refunds: false`. Wavex prints labels only for the batches
  it groups parcels into, so the merchant prints from the Wavex portal.
- **The courier collects more than the amount to collect.** On COD, Wavex adds its own shipping
  charge on top of the amount we send. For example, 100 EGP sent means the courier collects 100 +
  Wavex's charge (85 in Cairo when tested). A shipment with nothing to collect is sent as prepaid and
  the courier collects nothing. Say this next to the amount when the chosen partner is Wavex, for
  example "Wavex adds its delivery fee to what the customer pays".
- **A cancel after pickup is refused**, since Wavex would charge a fee for it. The answer is the
  usual `409 carrier.booking.notAllowed`, and the merchant cancels from the Wavex portal if they
  accept the fee.
- ~~**States arrive by polling only** for now. Wavex can push them, and that comes in a later drop.~~
  Pushed since Part 2.

## 1. Merchant screens

**Connect form.** `GET /api/carriers` lists Wavex with two `fields`:

```json
{ "code": "wavex", "fields": [
    { "key": "token",            "kind": "SECRET",          "required": true,
      "label": "API token (from the Wavex seller portal)" },
    { "key": "pickupLocationId", "kind": "PICKUP_LOCATION", "required": false,
      "label": "Pickup address" } ],
  "capabilities": { "labels": false, "cancel": true, "tracking": true, "returns": false,
                    "exchanges": false, "refunds": false } }
```

The token is created in the merchant's Wavex seller portal. **Test Connection**
(`POST /api/carriers/wavex/test`) returns the account's saved Wavex addresses as `pickupLocations`,
exactly like Bosta's pickup locations:

```json
{ "pickupLocations": [
    { "id": "019ed511-…", "name": "المكتب", "address": "شارع 9", "isDefault": true },
    { "id": "019f…",      "name": "المخزن", "address": "شارع 10", "isDefault": false } ] }
```

Fill the `pickupLocationId` dropdown from it and send the choice in `options`. If it is left
empty, Wavex collects from the account's default address. A wrong token is the usual credentials
error (`422`). Mapping sender locations to other Wavex addresses works as on Bosta.

**Shipment screen.**
- **Cancel** is available before pickup. After pickup the answer is `409
  carrier.booking.notAllowed` (see above).
- **Print** is hidden (`capabilities.labels: false`).
- **Timeline:** Wavex's own state word is the carrier code, and the label is that word with spaces
  (`out for delivery`). A failed delivery attempt (`trial1` to `trial3`) is an issue that the courier
  retries after.
- **Account refusals:** an empty Wavex wallet, or a route Wavex has no price for, reaches the
  merchant as `422 carrier.booking.accountNotReady`.

**Returns.** These are off until an admin turns them on (`capabilities.returns`). When on, a return
is a Wavex return order: it is collected from the customer and brought to the connection's pickup
address. There is no refund (`refunds: false`): a `refundAmount` is refused with
`422 REFUND_NOT_ALLOWED`.

## 2. Admin screens

`GET /api/admin/carrier-platforms` lists `WAVEX`:

```json
{ "platform": "WAVEX", "carrierFields": [
    { "key": "returns",   "kind": "BOOLEAN", "required": false, "defaultValue": false },
    { "key": "syncToken", "kind": "SECRET",  "required": true,  "defaultValue": null } ] }
```

**Create** (`POST /api/admin/carriers`):

```json
{ "code": "wavex", "platform": "WAVEX", "nameEn": "Wavex", "nameAr": "ويف إكس",
  "settings": { "syncToken": "…" } }
```

The sync token is any Wavex seller token, which Wavex needs even to list its cities. It works
exactly like Wingezz's sync account (`2026-10-23-wingezz.md` Part 1 §2):
- `secretsSet` is returned instead of the value;
- a blank or left-out secret keeps the saved one;
- `422 carrier.syncAccountRejected` comes back from the area sync when Wavex refuses it.

Wavex lists about 500 cities under 28 governorates.

---

## 3. Known limits

- **The amount the customer pays** is COD plus Wavex's delivery fee (see above). Rawafid does not
  quote or subtract that fee.
- **A booking whose answer is lost** is asked for once more and answered with the same parcel, so
  this rarely matters. If Wavex still doesn't answer, the shipment ends `FAILED` with
  `shipment.notConfirmed`, as on Wingezz.

# Part 2 — Wavex status pushes

**Status: deployed to staging (PR #64, 2026-10-24).** A test connection registered its webhook on
connect. A parcel booked through staging and then cancelled on Wavex's side was `CANCELLED` on
staging within seconds, carried by the push (the next poll was minutes away). The test webhook was
removed afterwards.

**No FE change and no API change.** Wavex states now reach a shipment within seconds of
happening, instead of within the polling interval. The timeline, statuses and notifications behave
exactly as before.

What happens behind the screens, in case support asks:

- **Connecting a Wavex account** registers a webhook on that Wavex account for this connection. The
  connect form and its answer are unchanged. If Wavex refuses the registration, the connection is
  still saved and is polled as before.
- **A connection made before this drop** is still polled. It starts receiving pushes the next time
  the merchant saves it (`PUT /api/carrier-connections/{id}`), even with only the name unchanged.
- **A new token** moves the registration to it. **Deleting a connection** removes its registration
  on Wavex. A deactivated connection keeps its registration, since its shipments are still tracked.
- Every push is checked against that connection's own secret. On arrival, Rawafid reads the parcel
  back from Wavex, so the timeline shows Wavex's answer.
