# Part 1 — Wingezz

> Builds on `2026-10-23-mega-technology-carriers.md` Part 1 (carrier-row `SECRET` fields,
> `secretsSet`, `capabilities.refunds`) and `2026-10-17-accurate-carriers-logos-returns.md` Part 1
> (admin-added carriers, `carrierFields`).

**Status: deployed to staging (PR #62, 2026-10-23).** On staging Wingezz (`wingezz`) is added and
enabled with its sync account (1,411 areas, every governorate placed). One test parcel was booked
through staging (waybill `64100022`), then cancelled through staging and confirmed gone on
Wingezz. It has no logo yet (`logoUrl: null`).

Wingezz has its own API (platform `WINGEZZ`). As with the Mega Technology carriers, an admin adds
it from the admin form and merchants connect, book, track and cancel. **No FE change specific to
Wingezz**: every screen is driven by `fields`, `carrierFields` and `capabilities`.

What is different, and what the screens must handle:

- **Cancel works and print doesn't.** `capabilities`: `cancel: true`, `labels: false`,
  `tracking: true`, `exchanges: false`, `refunds: false`. Wingezz's airway bill is a web page, not
  a PDF, so nothing is printed through Rawafid yet.
- **No pickup to choose.** Wingezz collects from the address it holds for the merchant's account.
  The preview's `pickup` is `null`, so show nothing to pick.
- **Wingezz's own rules can refuse a booking.** While the merchant's Wingezz wallet is empty,
  Wingezz refuses an amount to collect under 70 EGP. We can't check that ahead (the wallet is on
  Wingezz's side), so it surfaces at booking as the existing `422` "The shipping partner refused the
  amount to collect" (`carrier.booking.codAmount`).

## 1. Merchant screens

**Connect form.** `GET /api/carriers` lists Wingezz with four `fields`:

```json
{ "code": "wingezz", "fields": [
    { "key": "username",            "kind": "SECRET",  "required": true,  "label": "Username" },
    { "key": "password",            "kind": "SECRET",  "required": true,  "label": "Password" },
    { "key": "allowCustomerToOpen", "kind": "BOOLEAN", "required": false, "defaultValue": true,
      "label": "Allow the customer to open the package" },
    { "key": "allowCustomerToPart", "kind": "BOOLEAN", "required": false, "defaultValue": false,
      "label": "Allow the customer to take part of the order" } ],
  "capabilities": { "labels": false, "cancel": true, "tracking": true, "returns": false,
                    "exchanges": false, "refunds": false } }
```

The two switches are sent as `options`, like Accurate's `allowToOpen`. A wrong login is the usual
credentials error (`422`).

**Shipment screen.**
- **Cancel** is available. A cancel of a parcel Wingezz already deleted succeeds; one Wingezz
  refuses (the parcel is past that point) is the usual `422 carrier.booking.notAllowed`.
- **Print** is hidden (`capabilities.labels: false`).
- States arrive by polling only. Wingezz's own state number is the timeline's carrier code, with
  its Arabic name as the label. A parcel Wingezz marks delivered or cancelled reads `delivered` or
  `cancelled`.

**Returns.** These are off until an admin turns them on (`capabilities.returns`). When on, they
work as on the Mega Technology carriers: no refund (`refunds: false`, a `refundAmount` is refused
with `422 REFUND_NOT_ALLOWED`).

## 2. Admin screens

`GET /api/admin/carrier-platforms` lists `WINGEZZ`:

```json
{ "platform": "WINGEZZ", "carrierFields": [
    { "key": "returns",      "kind": "BOOLEAN", "required": false, "defaultValue": false },
    { "key": "syncUser",     "kind": "SECRET",  "required": true,  "defaultValue": null },
    { "key": "syncPassword", "kind": "SECRET",  "required": true,  "defaultValue": null } ] }
```

**Create** (`POST /api/admin/carriers`):

```json
{ "code": "wingezz", "platform": "WINGEZZ", "nameEn": "Wingezz", "nameAr": "وينجز",
  "settings": { "syncUser": "…", "syncPassword": "…" } }
```

There is no host to type in: Wingezz has one API. The sync account is a Wingezz account login;
Wingezz needs it even to list its areas. It works exactly like
`2026-10-23-mega-technology-carriers.md` Part 1 §2:
- `secretsSet` instead of the values;
- a blank or left-out secret keeps the saved one;
- `422 carrier.syncAccountRejected` from the area sync when Wingezz refuses it.

## 3. Known limits

- **A booking whose answer is lost cannot be found again.** Wingezz has no lookup by our id, and
  a repeated booking makes a second parcel. Such a shipment ends `FAILED` with
  `shipment.notConfirmed`, as in `2026-10-23-mega-technology-carriers.md` Part 1 §3. Show that
  message prominently.
- **States between "created" and the end** are shown on the timeline but don't move the shipment
  yet. We've only seen Wingezz's first state number live. Delivered and cancelled come as flags of
  their own and do move it.
